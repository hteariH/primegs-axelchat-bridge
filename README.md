# primegs-axelchat-bridge

Мост **prime.gs → AxelChat**: опрашивает чат [prime.gs](https://prime.gs) и переливает
новые сообщения в локальный API [AxelChat](https://github.com/3dproger/AxelChat)
(`POST /api/v1/receive-events`, появился в AxelChat 0.44.0).

AxelChat нативно prime.gs не поддерживает, но его HTTP-эндпоинт `receive-events`
предназначен ровно для сторонних интеграций — исходники AxelChat трогать не нужно.

Зависимостей нет — только стандартная библиотека Python 3.

## Как это работает

```
  prime.gs                  primegs_bridge                 AxelChat
 (REST-чат)                  (этот мост)                 (локальный API)
     │                            │                            │
     │  GET /chat/{id}/messages   │                            │
     │  ?period=…&since_id=…      │                            │
     │ ◀──────────────────────── │  опрос каждые interval сек  │
     │  ──────────────────────▶  │                            │
     │   новые сообщения (JSON)   │                            │
     │                            │  конвертация в формат      │
     │                            │  события AxelChat          │
     │                            │  POST /api/v1/receive-events│
     │                            │  ─────────────────────────▶│
     │                            │                            │ сообщения
     │                            │                            │ в оверлее
```

1. **Опрос prime.gs.** Мост дёргает REST-эндпоинт чата
   `GET https://prime.gs/chat/{chat_id}/messages` с параметрами `period`, `limit`
   и `since_id`. Параметр `since_id` — это id последнего уже обработанного
   сообщения, поэтому каждый запрос возвращает только то, что появилось после него.

2. **Стартовый baseline.** При запуске мост один раз читает текущие сообщения и
   запоминает максимальный `id` как стартовый `since_id` — чтобы не вывалить в
   оверлей всю историю чата. С флагом `backfill` стартовая пачка всё же
   отправляется.

3. **Вычитка с пагинацией.** На каждой итерации функция `drain()` забирает все
   сообщения новее `since_id`, при необходимости листая страницы по флагу
   `has_more` (до 20 страниц за итерацию), и сдвигает `since_id` вперёд.

4. **Конвертация формата.** Каждое сообщение prime.gs превращается в событие
   AxelChat (`build_event()`): автор с `serviceId = "primegs"` и иконкой платформы
   (`serviceBadge`), цвет ника, бейджи (`rightTags`), текст, курсив для
   `is_action`, отметка удаления. Время приводится из ISO 8601 prime.gs к формату
   AxelChat (`YYYY-MM-DDTHH:MM:SS.mmm`).

5. **Отправка в AxelChat.** Пачка событий уходит одним `POST` на
   `http://127.0.0.1:8356/api/v1/receive-events`. AxelChat показывает их в оверлее
   наравне с нативными платформами.

6. **Устойчивость.** Если AxelChat не запущен или сеть недоступна — мост логирует
   ошибку и продолжает крутиться, не падая. Остановка — `Ctrl+C`.

`serviceId = "primegs"` нет в списке штатных платформ AxelChat, поэтому это
кастомный идентификатор; значок платформы у сообщений берётся из
`serviceBadge` (`https://prime.gs/favicon.ico`).

## Как узнать свой `chat_id`

`chat_id` — это **число**, а не название стрима. В адресе стрима его нет:
например, у стрима `https://prime.gs/cmdshka` (это просто имя) `chat_id` равен
**37**. Ниже — два способа его достать; начните со Способа 1.

### Способ 1. Через исходный код страницы (самый простой)

1. Откройте страницу своего стрима в браузере (например `https://prime.gs/cmdshka`).
2. Нажмите **Ctrl + U** — откроется исходный код страницы.
3. Нажмите **Ctrl + F** и впишите в поиск: `/chat/`
4. Браузер подсветит фрагмент вида `/chat/37/messages`. Число между `/chat/` и
   `/messages` — это и есть ваш `chat_id` (в примере **37**).

### Способ 2. Через инструменты разработчика (если Способ 1 не сработал)

1. Откройте страницу своего стрима и нажмите **F12**.
2. Перейдите на вкладку **Network** («Сеть») и впишите в фильтр: `messages`
3. Нажмите **F5** (обновить) и дождитесь загрузки чата.
4. Кликните по запросу `messages?period=...` и посмотрите его Request URL:
   `https://prime.gs/chat/37/messages?period=current_stream&limit=50`. Число
   между `/chat/` и `/messages` — ваш `chat_id`.

## Запуск из исходника

Рядом с работающим AxelChat:

```bash
python primegs_bridge.py 1299
```

где `1299` — id чата из URL `https://prime.gs/chat/1299/messages`.

### Конфиг

`chat_id` и прочие параметры можно один раз прописать в `primegs_bridge.json`
рядом со скриптом, тогда запуск сокращается до:

```bash
python primegs_bridge.py
```

Скопируйте `primegs_bridge.example.json` в `primegs_bridge.json` и впишите свой
`chat_id`. Если файла нет, программа создаст шаблон при первом запуске.
Аргументы командной строки, если переданы, перекрывают значения из конфига.

| Параметр   | По умолчанию              | Описание                                         |
|------------|---------------------------|--------------------------------------------------|
| `chat_id`  | —                         | id чата prime.gs (обязателен)                    |
| `axel_url` | `http://127.0.0.1:8356`   | базовый URL локального AxelChat                  |
| `interval` | `2.0`                     | пауза между опросами, сек                        |
| `period`   | `current_stream`          | параметр `period` запроса к prime.gs             |
| `limit`    | `50`                      | limit сообщений на запрос                        |
| `backfill` | `false`                   | отправить и стартовую пачку уже существующих     |

## Готовый .exe

Не хотите собирать сами — скачайте готовый `primegs_bridge.exe` со страницы
[Releases](https://github.com/hteariH/primegs-axelchat-bridge/releases). Положите
его в любую папку, рядом создайте `primegs_bridge.json` (или запустите exe один
раз — он создаст шаблон), впишите `chat_id` и запускайте при работающем AxelChat.

## Сборка .exe (Windows)

Запустите `build_exe.bat` — он установит PyInstaller и соберёт один файл
`dist\primegs_bridge.exe`. Положите рядом с ним `primegs_bridge.json`
(или запустите exe один раз — он создаст шаблон).

Нужен установленный Python с галочкой «Add python.exe to PATH».
